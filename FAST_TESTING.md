# Fast Testing Protocol (GCP)

This document describes the high-speed testing protocol for Launchpad using a localized GCP single-node stack. This setup is designed to provide a repeatable, low-cost environment for verifying component changes (like `k0s`) in minutes.

## 1. Prerequisites

- `gcloud` CLI authenticated and configured with a project.
- `terraform` installed.
- `launchpad` binary built (run `make local` in the repository root).

## 2. Quick Start (The "Fast Path")

Navigate to the test stack directory:
```bash
cd examples/terraform/gcp-simple/
```

Bring up the infrastructure and generate `launchpad.yaml`:
```bash
make up
```

Apply the current Launchpad build:
```bash
make launchpad-apply
```

## 3. Deployment Verification

To verify the cluster state without leaving your terminal:

```bash
# Check k0s status on the node
ssh -i id_rsa ubuntu@$(terraform output -raw public_ip) "sudo k0s status"

# Run kubectl commands through k0s
ssh -i id_rsa ubuntu@$(terraform output -raw public_ip) "sudo k0s kubectl get nodes"
```

## 4. Key Design Decisions for Speed

- **Spot Instances**: Used by default (`spot = true`) to reduce cost by ~70-90%.
- **Wait for SSH**: Terraform includes a `terraform_data` resource that polls for SSH availability, ensuring the node is ready for Launchpad the moment `terraform apply` finishes.
- **Cloud-Init Pre-provisioning**: Dependencies like `socat` and `nfs-common` are pre-installed via `user-data`, and `ufw` is disabled to prevent common networking blockers.
- **Service Probing**: During installation, we prioritize `systemctl status k0scontroller` for readiness checks, as `k0s status` can be flaky while the service is still initializing.

## 5. Clean Up

Always tear down your stack when finished to avoid unnecessary costs:

```bash
make clean
```
This command destroys all GCP resources and removes the local `launchpad.yaml` and SSH keys.

## 6. Troubleshooting

- **SSH Authentication**: If you see "Too many authentication failures", the `rig/v2` integration is configured to ignore the SSH agent and use the explicit `keyPath` generated by Terraform.
- **IAP Access**: If your local network blocks port 22, you can still access the node via:
  ```bash
  make gcloud-ssh
  ```
